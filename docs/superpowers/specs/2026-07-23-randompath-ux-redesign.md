# RandomPath UX 大改造 · 设计方案

## 背景

RandomPath 骑行路线生成器功能完善（路线引擎、高德 API、100 条预设路线），但交互流程太繁琐：
- 每次生成路线要填起点、终点、选方向、调时长… 10 步才能看到结果
- 首页 ExploreView.vue 302 行塞满了所有逻辑
- Canvas 缩略图只画路线轨迹，没有沿途信息

**目标**：保留核心算法，重写交互层。打开 App → 一键出路线。

---

## 设计原则

| 原则 | 说明 |
|------|------|
| **一键优先** | GPS 自动定位，90% 场景不需要调参数 |
| **滑动 > 打字** | 滑块选时长、卡片选模式，少打字多点选 |
| **渐进展示** | 常用在前面，高级选项折叠 |
| **缩略图有料** | Canvas 标注上坡段、补给点、村庄、地形 |

---

## 交互流程

### 现有流程（10 步）
```
打开 → 选场景 → 展开自定义 → 填起点 → 编码 → 填终点 → 编码 
→ 选方向(8按钮) → 选时长(5按钮) → 点生成 → 等12次重试 → 看到结果
```

### 新流程（4 步）
```
打开(GPS自动定位) → 滑选时长 → 点🎲出发 → 5秒出路线
```

## Canvas 缩略图增强

新增标注元素：

| 元素 | 颜色/样式 | 数据来源 |
|------|----------|---------|
| 路线轨迹 | 粉色半透明 + 实线 | segments polyline |
| 上坡段 | 红色粗线 + ↗坡度%标签 | calcSlopeProfile |
| 下坡段 | 绿色粗线 + ↘坡度%标签 | calcSlopeProfile |
| 补给点 | 紫色圆点 + 白色序号 | searchAlongRoute |
| 村庄/居民点 | 黄色圆角矩形 + 名称 | 新增 useRouteContext |
| 指北箭头 | 灰色 ↑北 | 固定位置 |

`useRouteContext.js`（新增）：从路线 polyline 采样点，调用高德逆地理编码识别沿途地名，分类为村庄/城镇/无人区。

## 实施策略

分 3 个阶段，每阶段可独立上线：

### Phase 1：首页简化（核心）
- 重写 ExploreView：GPS 定位 + 模式卡片 + 时长滑块 + 大按钮
- 新增 TimeSlider.vue、SceneCards.vue
- 高级选项折叠
- **验证**：打开页面 → 滑动 → 点按钮 → 出路线，≤ 4 步

### Phase 2：结果页重做
- 新增 ResultView.vue（从结果卡拆出来）
- 增强 RouteThumbnail：上坡段着色、补给点标注
- 沿途信息条 + 路线文字描述
- **验证**：结果页信息密度提升，一眼看到关键信息

### Phase 3：沿途上下文
- 新增 useRouteContext.js
- Canvas 标注村庄/居民点
- 自动补给点搜索（生成路线时自动触发）
- **验证**：缩略图展示丰富的沿途信息

---

## 不变的内容

- 经典路线（PresetView）：100 条路线全部保留，交互小幅优化
- PWA 离线支持：vite-plugin-pwa 配置不动
- 高德 API 封装：useAMap.js 不动
- GPX 导出、导航链接、分享图：功能全部保留
- Hash 路由：`#/explore`、`#/preset` 保持不变
